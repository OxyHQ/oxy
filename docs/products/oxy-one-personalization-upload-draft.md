Mention uses only `user.personalization.mentionMono` from uncached `users.me({cache:false})`. The private current-user GET and profile-update response compute this product-specific read model from a live individual pro/business period or the exact configured product/capability. The two legacy subscription tables grandfather the existing profile-premium eligibility; their plan names do not prove a registered consumer product or an Alia plan. Their current start/end periods are checked explicitly. Generic bundle premium, arbitrary products grant no mono authority. Existing premium brand-color eligibility is preserved independently. The canonical preset is Bloom `mono`; `monochrome` is rejected. Color and themePreference writes, including account color updates, validate permission server-side; `oxy` retains the existing matching-handle or premium eligibility. Stored appearance is retained on expiry, while Mention falls back visually, refreshes cancellations and refuses saving mono without current permission. No translation/basic customization/privacy paywall is added.

Migration0148 only admits canonical mono in the database constraint. It is a pre-deploy draft migration applied solely by the throwaway test harness. No production migration or capability registration occurred.

Configured presigned uploads sign exact admitted size, checksum and If-None-Match:* and expire in60seconds. `assets.putPresignedUpload(init,blob)` propagates required headers, uses transport-derived Content-Length, and sends no Oxy bearer/cookies to the bucket. It rejects redirects, non-HTTPS targets, unexpected headers and failed conditional PUTs. Current Oxy FileManagement/Noted/Mention callers upload through the direct SDK API; this helper supports explicit `/assets/init` consumers without claiming existing clients were migrated to it.

`config/drafts/oxy-one-upload-cors.template.json` is a review-only PUT rule with placeholder approved origins. Merge it with existing bucket rules after exact-origin/provider review; never overwrite a production bucket configuration from this draft. Its contract test checks required headers and excludes wildcard origins/Authorization. No bucket CORS was read or changed. Browser/native end-to-end verification against an approved non-production bucket remains a release gate, distinct from the passing SDK transport and offline signing tests.


Approved display prices are independent of provider IDs. Synthetic checkout tests reject a mapping whose amount/currency disagrees with the published offer version and pass monthly/no-trial terms to the adapter. Before any real provider adapter is enabled it must prove registered price amount/currency, monthly recurrence, no trial and exact provider namespace; this source does not call a provider or mint a price ID.
