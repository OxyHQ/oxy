## Voice policy: preserve the existing product

Alia base revision f3608abb5ac1507b82366f757aa25d095908b5c4 serves `POST /v1/audio/speech` to every authenticated user. It checks input and optional message ownership, then calls `synthesizeSpeech` and uploads audio. It performs no subscription/capability lookup, credit admission or settlement. The UI gates voice calls on `voice-mode`, but that is not a server-side restriction on standalone speech/read-aloud. There is no evidence that a legacy balance is required by that endpoint. The draft's bundle-specific 503 introduced a restriction, including for users holding individual subscriptions; it is removed. Central snapshot staleness/conflict/overlap cannot change admission because this endpoint no longer uses the bundle as authority. This preserves existing product behavior, rather than treating standalone speech as a new monthly-credit benefit. The existing lane is unmetered in Alia credits; Oxy still measures inference internally. No claim is made that provider work costs nothing.

A voice call comprises device recognition, an ordinary credit-metered chat turn and standalone speech playback. Device recognition has no hosted inference charge. Episode speech remains within the existing show fixed-cost pipeline. ADR 0013 retires voice minutes; do not recreate a per-minute allowance.

The normal allocation reservation and settlement machinery **can** be reused if an explicitly approved future policy meters standalone speech. The technical gap is not a missing USD-to-credit conversion: `credit-price-snapshot.ts` already pins USD_PER_CREDIT=0.001, minimum/request=1 and formula version. Chat `CreditUsage`, `ModelPricing` and captured price books currently preserve only token quantities and input/output-per-million rates. They cannot correctly represent characters or request fees. Feeding characters as tokens or calling `finalizeCredits` with zero tokens would silently use a fallback/minimum, not a speech policy.

Available evidence: Oxy speech admission knows exact character count and one request (`inferenceEdge.service.ts: ceilingForOperation`); duration-priced routes without a sound ceiling are refused. Oxy generation records have request/account/application/environment attribution, exact unit quantities, pinned tariff/version or an unpriced state. V1 receipts additionally carry unit prices, exact billed amount/currency and platformFeeOnly. V2 internal records explicitly report customerCharge=not_charged and quoted/unpriced tariff. Alia's speech helper currently returns only audio, format and requestId. Tariff is not upstream cost, and billedAmount/platformFeeOnly cannot be assumed to be the Alia allowance basis. This is source evidence, not verification of an active provider, usable price or production scope.

If metering is later requested, the minimal consistent design is to reuse the approved credit formula with an immutable Oxy-pinned speech quote in the same allowance operation: exact requests/characters, USD unit rates/version and ceiling admitted before egress; stable upstream idempotency key; settle actual verified units through the existing fixed-count tracked finalizer; bind receipt/record to the same subject/app/environment/operation; retain holds on unknown completion and reconcile by request/idempotency key without another paid call. Reuse free/individual/bundle source selection and existing expiry/cancellation protections, not a separate balance. Unknown/unpriced/unsupported currencies must fail before new metered work, not receive a guessed price. Approval needed is whether standalone speech should consume Alia allowance at all, and if so whether the existing published tariff basis, rounding/minimum and treatment of request fees, failed/canceled work and cached replay apply. There is no reason to request this decision for the approved bundle launch while preserving existing standalone speech.
