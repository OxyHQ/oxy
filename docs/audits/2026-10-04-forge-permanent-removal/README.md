# Permanent Forge removal

The actual dependency graph replaces the two Expo tooling consumers of Forge with explicitly identified private native packages. `@oxy.so/expo-code-signing-native@0.1.1` implements the synchronous certificate/CSR/signing API with Node/OpenSSL cryptography and maintained Peculiar ASN.1 schemas. `@oxy.so/expo-cli-native@57.0.23+oxy.native.1` preserves 795 upstream CLI files and changes only package identity/dependency metadata and its certificate DN reader; its stale source map is removed. This is a maintained private tooling fork, not an official Expo release. The verified upstream is 57.0.23; discovering a later 57.0.27 release did not change that identity.

The root overrides replace Expo package boundaries. They do not rename or alias `node-forge`, suppress audit results, or extend an exception. The real Bun lock and installed API/CLI resolution contain no Forge. The previous patch is no longer active, and the declarative exception is valid `INACTIVE` with its four activation fields null. Existing ordinary security audit, merge-queue CI, image provenance and publication paths remain mandatory. Historical Forge approvals, patches and evidence remain historical.

`verify-native-expo-forks.py` verifies authenticated upstream archive integrity, every permitted fork delta, the native archive's source identity, and actual installed API/CLI package files. Package manifest formatting is compared semantically; code and every other file are byte exact. The immutable native artifact was advanced to 0.1.1 because overwriting the same file dependency left Bun's earlier installed contents cached, even with `--force`. Installed contents are now checked against the new immutable archive. The CLI's own Security.js executes against an independent OpenSSL EC certificate fixture and reads CN/O/OU without imposing an RSA-only DN parser.

Validation includes 36 native/public API and standards controls, 14 checks against the installed Expo API, seven archive/graph controls, five actual-image inventory controls, strict adapter declarations, API build, and a fresh owned PostgreSQL run of the 34 Oxy update-signing/manifest checks with the normal 142-migration fresh/repeat rehearsal. OpenSSL interoperability and malformed DER, CSR, certificate, key type and known-key noncanonical DigestInfo controls are independent of the prior Forge test suites. Synthetic private keys stay in memory or removed private temporary directories.

Six rebuilt shipping SDK archives were inspected: core, contracts, services, protocol, db and mcp have no file/workspace/catalog/private-tooling references in published manifests. The private archives occur only in the root tooling graph and frozen Docker inputs. This change does not publish SDK packages or mutate production.

The additional `native-expo-image-proof.yml` workflow admits only this same-repository PR branch, checks its exact source SHA and valid inactive policy, and builds the actual linux/arm64 production OCI archive without AWS credentials, id-token permissions or publication. It records raw manifest/config/build metadata, checks image/config identity and source/platform, scans the actual image for physical Forge copies and verifies installed native package bytes, then runs the 14 installed Expo controls inside that image. The proof mount is first proven absent and does not overlay `/app`. Local host validation does not claim this ARM run has succeeded; its authenticated run/artifact and independent review remain necessary before acceptance. None of the previous 321 Forge checks are attributed to this native image.

The canonical dependency audit passes with six existing high advisories in two previously acknowledged packages, zero critical advisories, and lower-severity findings. This is a Forge removal claim, not a claim that all dependencies are advisory-free.
