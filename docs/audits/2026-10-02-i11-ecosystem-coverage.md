## Evidence boundaries

Enumerated with `gh api orgs/OxyHQ/repos --paginate`, then `gh api repos/OxyHQ/<repo>/commits/<default_branch>` and `gh api repos/OxyHQ/<repo>/git/trees/<sha>?recursive=1`: **50 accessible repositories, 50 full trees, zero truncated trees**. Every row has actual inspected file contents, not a classification inferred from its name. The [machine-readable evidence](2026-10-02-i11-ecosystem-coverage.json) records every inspected path/blob SHA, manifest dependency/group/line, effective catalog value, lockfile resolution key/line, available test script and registry observation. Inspection is selective; uninspected imports, binaries and services may change a classification after further review.

Declared means a manifest range (with `catalog:` resolved through the root catalog); resolved means a tracked lockfile record, including nested copies and workspace source. Neither means installed code was executed. Published means an exact version or latest metadata response from the public npm registry, with integrity and HTTP observation date; registry metadata is not a tarball compatibility test. Deployed requires a running image digest or APK/web artifact, source mapping and actual resolved dependencies. **Deployment is unverified for all 50 rows.** No production IAM, provider request, Stripe operation, persistent credential, grant or device mutation was performed.

Candidate PRs and local foundations are separate from default-branch and registry evidence: #1530/#1532/#1534 (identity/authority), #1529/#1533/#1535 (billing), #1531 and inference followups, Peable#88/#89. Reported unit/integration counts on those candidates do not certify combined adoption. Peable SDK candidate 0.2.0 remains unpublished; registry latest is 0.1.1. Every repository keeps its own build/deploy pipeline.

## Update proposals, regression and rollback

`python3 scripts/audit-i11-coverage.py` validates the immutable evidence and prints **read-only review proposals** for observed version gaps. `--online` additionally compares accessible repo sets and current default heads, detecting inventory/head drift without changing manifests or credentials. The proposal records package/workspace/range, locked version, registry observation and the consumer's actual test script; it is not a semver approval or an executed migration. No test-script absence or `echo "No tests specified"` counts as coverage. New I04/I07 versions must replace the provisional registry targets after one coordinated release.

After the contract and commercial decisions already pending in #1519 are resolved: build/test/pack each changed common package in its own release command (`bun run build && bun pm pack`), inspect CJS/ESM/types/native export targets and package integrity; use an isolated consumer worktree, regenerate `bun.lock` with `--minimum-release-age=0`, run its real manifest/lock sync checker and package-specific `bun run test`, build and strict typecheck. Commit each dependency manifest together with its lockfile. Create reviewable update PRs; breaking changes receive no automatic deploy. Keep source tests distinct from packed-consumer tests and deployed smoke tests.

Rollback requires previous published package/tarball integrity, previous manifest+lockfile commit, deployment image digest or APK/web build ID, feature/cutover state and migration reversibility assessment. Payment rollback reconciles immutable grants and provider/event IDs; it does not re-run awards, delete subscription state or claw back historical balances. Identity rollback does not restore revoked membership/grants or delete device keys. Do not remove duplicate implementations until the replacement is adopted and compatibility is demonstrated on the affected consumer. See the [final acceptance ledger](../architecture/i11-final-acceptance.md).
