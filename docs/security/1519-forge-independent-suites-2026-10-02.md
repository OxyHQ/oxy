## Expo harness and first-run correction

The [independent harness](../../scripts/forge-independent-expo-compat.cjs) uses
published Expo `@expo/code-signing-certificates@0.0.6` from the exact frozen Oxy
installation, resolving the installed patched Forge. It exercises RSA/PEM round
trips, self-signed certificate validation, Expo manifest signing verified by
Node/OpenSSL, altered-message rejection, wrong-key rejection, invalid and
expired validity intervals, CSR signature/PEM round trips, development
certificate issuance and project scope, and rejection of an altered CSR.
These are 14 own public-API checks; the Expo upstream suite was not executed,
as the published package omits its test fixtures and configuration.

The first harness run had 12 passing and 2 failing assertions. The candidate
rejected the wrong key by throwing Forge's padding error earlier than the
harness's anticipated Expo message. The other assertion passed an OID string
to `getExtension` instead of its `{ id }` argument. The harness was corrected
to require an exception for the wrong key and to use `{ id }`; candidate source
and dependencies were unchanged. Both [initial](forge-independent/2026-10-02-b09309b/expo-14.log)
and [final](forge-independent/2026-10-02-b09309b/expo-14-final.log) logs are retained.

## Boundaries and remaining gates

The malformed-input controls sign synthetic structures using a private key
known to the test. They do **not** reproduce a low-exponent forgery without the
private key. MD2 has no Node/OpenSSL oracle in this harness; its controls use the
RFC vector. Browser bundles run in a Node VM with inert jQuery stubs; this is
not browser, Hermes, Android or OTA device parity. No certificate authority or
production identity was involved.

Passing these checks establishes reproducible bytes and the exercised
compatibility behavior. It does not establish an upstream fix, a fixed audit
version, exploit completeness, ARM64 image equivalence, production adoption,
audit-exception authorization or general security approval. The [GitHub advisory](https://github.com/advisories/GHSA-86w9-cpqp-85rv)
listed affected versions through 1.4.0 and no patched version when checked on
2026-10-02. The no-private-key exploit reproduction and policy/authority gates
remain open. The integration agent's separate artifact/provenance review stays
separate from this local source/suite reproduction.
