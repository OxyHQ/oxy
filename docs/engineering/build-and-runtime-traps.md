# Build freshness, bundling and runtime traps

Each bullet is a rule that held up after a build or check reported success while measuring or shipping the wrong thing. Evidence is kept to the mechanism; verify the version-specific behaviours against the versions in use.

## Build-freshness traps

- **Metro's transform cache is keyed by file content, not by the build's environment.** `EXPO_PUBLIC_*` substitution is silently skipped when an earlier build of the same unchanged source is cached, including in a shared cache another project populated; the bundle then carries the committed fallback value (for example a client id for the wrong Oxy application) with exit 0. `--clear` fixes it. **Verify the value in the built bundle** (grep the bundle for the expected id), never the exit code. A fallback that is plausible in production is what makes this invisible.
- **Swapping `node_modules/<pkg>` between runs does not invalidate Metro's cache.** Gate a native verification run on a rendered value only the current source can produce; on-disk `src/` reads fresh even when the served bundle is stale. Never `rm -rf` a shared metro cache in `/tmp`; use a dedicated `METRO_CACHE_ROOT`.
- **Verify the artefact the consumer loads.** For an Oxy React Native package the `"react-native"` export condition points at published `src/`: Metro compiles source, and `lib/` only serves Vite, Node and `tsc`. Verify from the registry tarball, not from the commit you believe was released.
- **A package can publish with no `lib/` and look fine from every angle you habitually check.** `npm publish <tarball>` runs no lifecycle scripts, so a `prepublishOnly` build never runs, and that is the property it is chosen for (the artefact you inspect is the artefact that ships). The release therefore builds once in the job that packs, packs with `bun pm pack --ignore-scripts`, and no package relies on `prepublishOnly`, `prepack` or `prepare` ([npm releases](../npm-releases.md)). `tsc` cannot see an empty `lib/`, because the `react-native` condition takes it into `src/`; web, Vite and Node consumers get a bundler failure, Jest reports "N suites failed, 0 tests failed" (a load failure), and ESLint reports `import/no-unresolved`. Assert a floor on packed entries and on the `lib/` count against a baseline. Reference gate: Bloom's [`scripts/verify-package.mjs`](https://github.com/OxyHQ/Bloom/blob/main/scripts/verify-package.mjs), which packs the tarball and asserts every `exports` path ships.
- **A workspace package's `version` equalling the published one proves nothing about its content.** A package can gain exports for weeks at an unchanged version; in-repo everything is green because the workspace resolves to `src/`, and the first consumer to install the registry copy fails at module load with `The requested module '…' does not provide an export named …`, an error that names the consumer, not the drift. Before bumping a dependency on a sibling package, diff the published tarball against the repository (`npm pack <pkg>@<version>`, compare the declarations), and bump the version: merging the bump is what publishes the current code.
- **turbo restores artefacts from a cache shared with your other worktrees**, and says so only in a replayed log line naming the other path. That is harmless when output depends only on source and dangerous when it is derived from the build (a generated CSP containing hashes of the built HTML's inline scripts can forbid the page's own script). Before deploying a cached build by hand, re-run with `--force` and diff the generated file.
- **A package whose suite reads its own `dist/` must be rebuilt between mutating and running**, or the failures are build skew. Run the suite once before mutating as a baseline. `rm -rf dist` does not restore a fresh state: delete `tsconfig.tsbuildinfo` too.
- **One package can be read two ways at once.** `tsc` resolves a project reference through `dist/` while Jest's `moduleNameMapper` loads `src/`. Mutating and typechecking without rebuilding exits 0 on stale declarations, a spurious green. Confirm the change is visible to the tool you are about to run.
- **`node_modules` staleness has four silent modes** (present but unlocked, locked but stale version, dead orphans, a partially failed install exiting 0), all compatible with a clean `git status` and a passing `--frozen-lockfile`. After any wipe and reinstall, assert the versions your gate depends on and scan installer output for `error:`; never trust its exit code. A sibling session landing a dependency commit invalidates your tree.
- **`node_modules` is shared across worktrees** (bun hardlinks from one cache). Editing a dependency file mutates it everywhere, and `mv backup.js original.js` does not restore other worktrees. Write the pristine content in place (`cat pristine > target`), sourced from `npm pack <pkg>@<version>`.
- **Hardlinking stops at the filesystem boundary, and `/tmp` is usually tmpfs, which is RAM.** An install into a worktree there copies instead of linking, costs gigabytes per worktree, and surfaces as `ENOSPC` mid-install or processes killed for low memory, neither of which names the cause. Put worktrees on the filesystem that holds bun's cache (`<repo>/.worktrees/`). `stat -c %h node_modules/react/package.json` reads 1 when it copied and more than 1 when it linked.
- **A clean `git status` and the right branch name are evidence about the checkout, not the repository.** Before "is X still on main", compare `git rev-parse HEAD` with `git ls-remote origin refs/heads/<branch>`. Before "unpushed means valuable", diff against `origin/<branch>`.
- **A snapshot or generated file made from a `dist/` built before a rebase describes the old tree.** `drizzle-kit generate` reads the schema through the `dist/` of `@oxy.so/db`, `contracts` and `core`; after rebasing onto a main that changed an enum there, regenerated snapshots silently dropped it, and overwriting the generated SQL with the reviewed SQL hid the diff. The local snapshot-sync check passed while CI (clean install, full build) wanted a constraint change. Rebuild after rebasing, and reproduce CI-only failures in a clean detached worktree with CI's own install and build; see "Renumbering a migration" in [`MIGRATION-CONTRACT.md`](../../packages/api/src/db/MIGRATION-CONTRACT.md).
- **A shell's cwd persists across tool calls.** After a `cd` into a sibling worktree, every later bare relative path silently addresses that tree: reads yield a wrong report, and a write (a formatter, `git checkout <path>`) can mutate or revert a sibling agent's uncommitted work. Address another tree with `git -C <path>` or an absolute path.
- **An agent that dies mid-rebase has not lost its work.** `ORIG_HEAD`, `rebase-merge/done` and `git-rebase-todo` hold the state to resume or reconstruct it; check them before assuming the branch reverted.

## Bun and Node

- **`setInterval` in a module-level singleton must release its handle**, or it hangs Jest non-deterministically. Diagnose with `--detectOpenHandles --runInBand`; never mask with `forceExit`. In a package that ships `src/` under the `react-native` condition, do not write `.unref?.()`: it guards the call, not the property access, and is a hard TS2339 wherever `setTimeout` returns `number`. Widen through `unknown` and narrow structurally (`typeof h === 'object' && h !== null && 'unref' in h && typeof h.unref === 'function'`); an inline `typeof x === 'object'` narrows `number` to `never` and fails too. Node-only packages may keep `.unref?.()`. The library's own `tsc` passes because its tsconfig pulls `@types/node` while its consumers' does not, so the gate is a consumer-shaped typecheck (`types: []`, the React Native lib, `customConditions: ["react-native"]`) over your own `src/` with a positive control that must fire. Reference: Bloom's [`scripts/verify-consumer-typecheck.mjs`](https://github.com/OxyHQ/Bloom/blob/main/scripts/verify-consumer-typecheck.mjs). The same applies to `@oxy.so/services` and `@oxy.so/core`.
- **The isolated linker (the default) does not hoist**, which breaks Dockerfiles that copy only the root `node_modules`. Set `linker = "hoisted"` in the monorepo-root `bunfig.toml` and copy it into the Dockerfile before `bun install`.
- **Subpackage lifecycle scripts must go through `bun run <script>`**: devDependency binaries live only in the root `.bin`, which is not on their PATH.
- **Pin the same bun version in CI `setup-bun` and in the Dockerfile**, or `lockfile had changes, but lockfile is frozen`.
- **ICU data moves with the Bun version.** Locale formatting changes between releases (for example the digit system of a bare `ar` locale), so a guard asserting native digits must name a locale or numbering system explicitly (`ar-EG`, `-u-nu-arab`). Re-run i18n guards on every Bun bump.
- **`COPY --from=oven/bun:<v> /usr/local/bin/bun` brings `bun` only, with no `bunx`.** Add `RUN ln -s /usr/local/bin/bun /usr/local/bin/bunx` and assert `bunx --version` wherever a build script calls `bunx`; the failure is invisible while the install layer stays cached.
- **`.dockerignore`:** `**/node_modules` and `**/dist`; BuildKit does not match a bare nested path.
- **A custom `lookup` for `https.request`** must return `[{ address, family }]` when called with `{ all: true }`, or the request fails with `results.sort is not a function` and surfaces as a 502.
- **`rate-limit-redis` needs a unique `prefix` per limiter** (`'rl:<scope>:'`) or `ERR_ERL_DOUBLE_COUNT`.
- **BullMQ on Valkey:** queue names and custom job or dedup ids cannot contain `:` (hash composite values into the id, or the job silently falls back); set `maxRetriesPerRequest: null`; under the isolated linker pass a plain connection-options object.
- **Never construct a second `new WebSocketServer({ server, path })` beside socket.io.** ws's own upgrade listener answers 400 to every non-matching upgrade and corrupts already-upgraded sockets. Use `{ noServer: true }` and one `server.on('upgrade')` router. Reference: Alia's [`mcp-relay.ts`](https://github.com/OxyHQ/Alia/blob/main/packages/api/src/lib/mcp-relay.ts).
- **Packers strip a file named `bunfig.toml`** from published tarballs. Ship it as `bunfig.toml.tpl` and rename on render, and run a scaffolder's CI from its packed tarball.
- **`--frozen-lockfile` is not a lockfile-sync check.** It passes on a stale workspace `version` and on a widened range, and a bare install-and-diff is blind to a version bump. Use two layers: compare what `bun.lock` records per workspace against the manifests, then run one plain `bun install` and ask git whether `bun.lock` moved. Reference: CrowdSource's [`scripts/check-lockfile-sync.mjs`](https://github.com/OxyHQ/CrowdSource/blob/main/scripts/check-lockfile-sync.mjs).
- **Bun can keep a stale nested copy in `bun.lock`** after an update moves the hoisted one (a nested `@oxy.so/contracts` beside the newer hoisted one the range accepts). Two copies are two module instances (two contract schemas, two Bloom contexts) and OxyOS's packager refuses them. `oxy-doctor --ci` (`@oxy.so/doctor`, in every app's CI) fails on it and names the fix, `bun update -r <pkg>`.
- **The hoisted linker leaves stale nested `node_modules`** after a per-workspace `bun add` or `remove`. After native-dependency churn: `rm -rf packages/*/node_modules && bun install`, then re-run expo-doctor.

## Metro web chunking

A module reachable from two `import()`-ed routes is hoisted into `/__common.js`, which Expo's static-export serializer emits as an unconditional `<script>`, so it downloads at first paint. There is no threshold or opt-out in the serializer versions Oxy apps have used, `customSerializer` is bypassed on that path, and `splitChunks: false` is strictly worse; the only serializer-level remedy is duplication. Quote marginal gzip size from an A/B build, never per-source attribution. Re-verify after an Expo upgrade.

## Reanimated (web): three distinct failure modes

- **(A) Animations started from mappers never tick.** Returning `withTiming` or `withRepeat` from `useDerivedValue` or `useAnimatedStyle` silently fails. Drive a `useSharedValue` imperatively; `useAnimatedStyle` only reads.
- **(B) Without the worklets Babel plugin (the production reality for Oxy React Native Web apps), every mapper re-runs on its dependency array, not on auto-tracked reads.** Omit an animating shared value from the deps and the mapper runs once and freezes. List every shared value the mapper reads. `useAnimatedReaction` does not fix this; key it on a changing prop, not a shared value.
- **(C) A custom `Keyframe` passed as `entering` freezes the element at about five times its duration**: a layout bug (`position: absolute` plus a frozen snapshot) with no console output, and `exiting` is unaffected. Verify position at more than five times the duration. Fix: drive the enter imperatively, or use a predefined builder.
- Jest and `tsc` catch none of the three. Verify in a real foregrounded tab: a hidden tab also freezes plain CSS transitions, which mimics "the class didn't apply". Read the class attribute or set `transitionProperty='none'` before reading computed styles.

## Hermes (mobile)

Hermes rejects Unicode property escapes (`\p{…}`) in `u`-flag regexes at runtime, though `hermesc` and V8 accept them. Verify on a real Hermes device build. The fix and the rule are in [package-rules.md](package-rules.md#hermes-property-escapes).
