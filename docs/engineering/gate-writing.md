# Writing a gate that can actually fail

Every rule here came from a check that reported clean while measuring nothing. A gate that stops measuring produces the same output as a repository that is clean, so the discipline is to ask of every check: **what would this report if the thing it measures were absent?** Assert that the wrong answer is not returned, not only that the right one is.

## Censuses, maps and pattern matching

- **A gate that skips what is missing from a hand-maintained map is not a gate.** Every item must be mapped or listed not-applicable; being in neither fails. Never derive the map from names (a Mongoose collection name, say), which produces a check that cannot fail. The same map class also silently deletes: a generator whose hand-maintained mount map still pointed at a deleted file dropped a live route from the published contract with exit 0 and a green build. When regenerating any artefact under a freshness gate, account for every removed entry in the diff; a pure-addition diff is the expected shape, and any removal is a bug until named.
- **`grep` is line-based.** A pattern that could span a newline matches nothing and reads as clean. Give it a vacuity floor or use single-line markers.
- **Anchor a marker grep**, or the marker's own explanatory prose inflates the count: use `^-- marker=…$`, not a bare substring. The same unanchored substring run over a production environment can name a different subsystem as "configured" (a search for `RELAY` in a task definition matched `SMTP_RELAY_*`). Re-run anchored to exact names, with a positive control proving the query could see what is present.
- **A skip list needs anchoring as much as a search pattern.** A skip entry `lib` silently dropped a real source directory from a census and the result was a clean, smaller number. Report the count of files a census examined, not just what it found, so a shrunken corpus is visible.
- **A guessed identifier produces a confident wrong reading, and "not found" is a question about the name first.** A probe for a guessed table name reported it missing; the real table had another name. Resolve an identifier against the schema or source before querying for it, and search the identifier form (snake, camel, kebab) as well as the prose form: a search for `"insufficient balance"` returns nothing when the code spells it `insufficient_balance`.
- **An alternation with wrongly ordered branches yields output that is clean, plausible and false.** `ts|tsx` matches `.tsx` as `.ts` plus a stray `x`, producing a tidy list of nonexistent paths. Put the longer alternative first, and confirm any census-produced file list exists (`test -e` per entry) before concluding anything from it.
- **After a port begins, a symbol-name census cannot tell the Mongo collection from the Drizzle table** (same identifier, different modules). Match on the import path, not the symbol.
- **A census over source must exclude comments.** A comment quoting a call inflates the count; a restore check whose marker appears in the function's own comment can never reach zero; and a count whose every hit is a comment saying the feature is unimplemented is evidence of the opposite of what non-zero suggests. This hits gates that forbid something hardest: the author has just been told why the rule exists and wrote the why next to it, so the better the comment the likelier it breaks the gate (a gate banning an action tripped on its own explanation; another passed a mutation because the flag was also named in a comment). **Assert against parsed structure, not file text** (`steps[].uses` from the parsed YAML, an AST node), or strip comments before matching. A gate over a file that also explains the gate cannot safely be a `grep`.
- **A census over TSX must walk `JsxText`, not just string literals**, or the most natural way to write a forbidden phrase (`<button>Rotate key</button>`) is invisible. Give it a negative control too: a census that also matched Tailwind's `rotate-90` was deleted by the next person who saw the false positive, and a false positive is not a safe failure mode.
- **Enumerate every syntactic form the target can take**, with a dedicated fixture per form that fails on its own vacuity floor if that branch is removed. A `keyGenerator` census matched only the long-form property assignment; a refactor made call sites emit the shorthand form, the count fell, and the gate's floor sat far below the true population, so it reported clean. A vacuity floor is a backstop against total breakage, not a measurement: where the count is meaningful, assert it moved as expected or record it.
- **A scanner narrowed to a convention its own package does not universally follow reports clean.** Assert the scan saw a known-present example of every variant it claims to handle (both quote styles, both import forms).
- **A name being read is not a URL being built.** A detector for outbound-link parameters that matched a column name, its type and a field read from a response fired on none of the constructions it meant to catch. Match a parameter name only where it can mean a URL (inside a query string, or as a setter's first argument), never as a bare identifier.

## Guard design, ratchets and migration checks

- **A guard can assert the shape of a declaration and never its semantics.** A regex for "no caller can omit the actor" misses a default parameter (`actor: T = {…}`), and "the writer calls `recordConfigChange`" is not "with the right payload". An AST assertion on the parameter node beats a regex; a branded type beats both.
- **"Post means it narrows" is the wrong test for a migration check.** The real test is whether it breaks a write the previous image performs. A check that only narrows future writes belongs in `pre` if no running image writes the forbidden value; marking it `post` strands it, because a zero-capacity deploy skips `post` entirely and every later `pre` queues behind it.
- **A gate whose input the migration deletes erodes to vacuity one defensible decrement at a time**, ending at `>= 0`. Decrement only alongside a registered equivalent landing in the same change; re-express against the destination at cutover.
- **`grep -c` exits 1 on a zero count**, so `mutate && grep -c X && run-tests` short-circuits before the suite runs and the silence reads as "mutation survived". Never hang verification off grep's exit status. `$?` after a pipe is the pipe's status, not the command's.
- **A progress signal that is only ever set is a ratchet, not a synchroniser.** Any "resolved" flag needs a path that clears it, or a reopened item stays reported as done.
- **A test file that throws at import reports as "N skipped"**, which reads benign; the fact is in the exit code.
- **Porting arbitrariness faithfully is not an option** (Mongo `$last` with no `$sort` has no Postgres equivalent). Choose defensible semantics and say so; `NULLS LAST` is then load-bearing, or a never-failed row sorts first under `DESC`.
- **Ask the cheapest-green question of constraints before writing the check.** A blanket `cardinality(x) >= 1` can reject the one row whose empty value is meaningful. Prefer an implication under the discriminant and defend the legitimate empty case with a fixture.
- **A gate that pushes you toward the hazard is worse than no gate.** A biconditional correct only while CI owns a secret fails a hand-managed one, and the obvious fix (adding the allow-list entry) arms a future deploy to overwrite a real credential. If the cheapest green is the dangerous action, the invariant is wrong.
- **A serious port bug fails by returning something plausible, not by erroring** (a boot exiting early, `eq()` used for containment, `DESC` with no `NULLS LAST`, a NULL keyset comparison, a migrator applying nothing and exiting 0).
- **A migrate entrypoint relying on a Bun compatibility shim (`__dirname` in ESM) is invisible to every local gate and fatal under `node:*-slim`.** Bun defines it, Node does not, and `@types/node` makes `tsc` accept it. Use `fileURLToPath(import.meta.url)`, and gate by executing the built artefact under `node` to a known later checkpoint.
- **A test supplying input the real caller never supplies measures the function, not the system.** A fully tested env-var opt-in that the calling workflow never forwards means production always takes the refusing branch. Assert the caller passes it, in the caller's own file.

## Controls and the type system

- **To prove a census's zero means absence and not blindness, inject a synthetic file exercising every claimed shape, confirm each counter moves, then remove it.** Pair it with a non-zero floor on found shapes.
- **A negative control needs its own vacuity floor.** "X is absent" is also what a scan that read nothing reports. Grepping an artefact for a marker that was never in it returns zero and can be misread as a clobbered file. A bare zero is uninterpretable: count each marker in the source first and compare counts against the target ("four before, four after"). A bare absence claim ("the repo contains no PEM file") is a guess in a measurement's clothes even with no grep involved; state a count and compare it.
- **A positive control only covers the failure mode it shares with the measurement.** A type probe whose imports fail to resolve can silently degrade to `any` while an unrelated literal-type-error control fires beside it. Ask what the control would do if the measurement's specific mechanism broke, and run probes inside the package, not beside it. The sharpest form is a regex anchored on a marker in a sibling's prose that reads one array twice under two names, where an exact-length control passes because it reads the identical wrong array; only a "the two parses differ" control catches it.
- **A property enforced by the type system needs a gate in the type system.** Moving a brand between two types can leave runtime tests green. Write one assignability assertion in the test tsconfig and mutation-test it.
- **A type system that does not cover the fake cannot gate anything living in it.** A package whose tsconfig excludes `src/**/*.test.ts` and `src/**/__tests__/**` (the oxy `api` package does) typechecks no test fake, so a new required field breaks the fakes at runtime while `tsc --noEmit` exits 0 on a red main: "both PRs green alone, combination red" is the expected outcome. Services' tsconfig shares the shape. Making a function's parameter required is the single most compiler-checkable breaking change there is, and in such a package the compiler reports success on the call sites that broke, because an `exclude` removes files from the program. In these packages the test run, not the typecheck, is the gate for any signature change.
- **A required property on a type reconstructed from a wire is a claim about what the far side sends, not an enforcement of it.** A completion type built from deserialized JSON leaves a field `undefined` at runtime when a producer omits it, and the consumer throws with `tsc` having signed off. The guard belongs at the consumer (a runtime assertion or a producer-walking test), never the annotation; "make the producers set it" is not a fix because the type system does not close the set of producers. An unguarded iteration past settlement in an Express 4 handler swallows the async rejection and the request never answers, so tests burn their full timeout instead of failing fast.

## Mutation testing and verification mechanics

- **A positive control naming production code as its known-positive has a shelf life equal to that code's.** Point it at code retired last, chosen explicitly, with the retirement condition written at the assertion.
- **A test that re-implements the code under test measures the re-implementation.** Coverage against a hand-written copy of a SQL statement stays green while the shipped statement regresses.
- **A mechanism can be green and inert at once.** Every target registered and every test passing, while the real entrypoint (`startExpirySweeper()`) has zero callers because tests invoke it directly. Assert the entrypoint calls it, with a vacuity floor proving the file is the entrypoint. The same holds at the other end of the pipe: a column that is written, CHECK-constrained and returned by the API is inert if the consumer discards it (a frontend that re-derived a label from another field would render identically with the column deleted). For a column added to make a distinction visible, assert the consumer reads it.
- **Two failures in opposite directions is what a genuine race looks like from inside a test.** Keep only the deterministic halves.
- **A surviving mutation on a line that "obviously does something" is a finding about the code, not a test gap.** `inArray(col, [])` renders as literal `false`, so an early return saves a round trip rather than guarding; an explicit write inside `onConflictDoUpdate` can be dead code the ORM already emits. Fix the comment, not just the test.
- **A surviving mutation usually means the fixtures are too tidy.** Ask what input makes the strict and loose versions disagree. Occasionally the opposite: an untidy but valid fixture surfaces a real missing constraint.
- **Restoring a mutation with `git checkout <file>` reverts your own uncommitted work too.** Keep a pristine copy, restore only the mutated hunk, and assert a marker from your own edit survives.
- **A mutation that never applied is indistinguishable from one that survived.** Diff the file immediately after editing, before running the suite. The counterpart failure is a write landing in the wrong place: an automated edit to a structured document anchors on content and asserts exactly one match, never a line number, which shifts under the edit's own earlier hunks.
- **`git diff` is empty for an untracked file**, so "prove the mutation applied" is vacuous there. Diff against a pristine copy.
- **A test can verify a path that is unreachable in production**, and the mock is usually what makes it reachable (a rollback test driven by a rejecting mock while the real system refuses earlier). Ask whether the path can occur at all before replacing a mocked test.
- **A byte-diff proves the file moved, not that the change is reachable.** A `s///` interpolating `$var` on the replacement side can insert dead code that a byte-diff confirms as "changed". Put a positive control on the mutation itself, asserting the inserted code references the real identifier.
- **A census used to bound or stop a search needs its positive control more than one used to enumerate.** A false zero from the wrong artefact reads as "this does not generalise", and that conclusion stops the looking.
- **A false measurement is least likely to be questioned when its result confirms the hypothesis.** A diff against a dotfile path (which ESLint silently ignores) returned zero matches and was read as "not pre-existing". The lesson is that zero was the answer that confirmed the belief, which is exactly when nobody re-runs the check.
- **Never write a label that interprets output you have not seen.** A pre-written `echo '--- (empty above = deleted) ---'` above output that showed the file present was read as deleted. Label what the command is, never what its result would mean; when a label and its output disagree, the output wins. A separate call per check has no gap between writing the interpretation and seeing the data.
- **"Local gates green" means nothing unless you ran the command CI runs.** `test` and `test:coverage` differ. Read the workflow and run its exact script.
- **A git pathspec of `dir/**/*.ts` misses top-level files in `dir/`.** Use a directory pathspec.
- **`git ls-files` is the right primitive for a repository-wide scan.** A missing working-tree file throws mid-run (record a failure), a narrow extension filter hides other languages, and an unstaged probe is invisible to it (`git add -f` before mutating). Its enumeration is scoped to the repository it runs in: a well-built gate with a real vacuity floor still does not see a file outside every repository's boundary, such as an instruction file in a plain directory that holds several repositories.
- **A harness can transform your probe into the thing you are probing for.** A hand-written escape-sequence-versus-NUL comparison can have its escape text turned into an actual NUL by the tooling. Generate byte-level probes from explicit byte values.
- **A NUL byte makes `grep` report a present symbol as absent** (exit 1, no output; `grep -a` finds it), and git's binary detection scans only the first 8000 bytes. Gate with an affirmative extension list, a scanned-file floor and a mutation test.

## Generated artefacts

- **Changing a generated column's expression makes `drizzle-kit generate` emit `DROP` plus `ADD COLUMN`, destroying every index over that column**, and drizzle re-emits none. The failure is silent (full-text search degrades to a sequential scan as the table grows). Hand-write `ALTER COLUMN … SET EXPRESSION` (check the server version supports it) and assert the index exists after the migration.
- **`drizzle-kit generate` exits 0 and leaves `drizzle/` byte-identical when the schema fails to load entirely.** "Regenerate and confirm no diff" is exactly what a total load failure also produces. Assert the table count loaded, not just the diff.
- **A generated artefact can be faithfully stale: current with its source, and wrong.** A regenerate-and-diff freshness gate passes by construction. When new route registrations were inserted between an endpoint's JSDoc and its own registration, the OpenAPI generator (which harvests the docblock immediately above a registration) silently stripped that endpoint's documentation, and a clean regenerate reproduced exactly that. A freshness gate is evidence about currency, never content; something separate must check the content. Account for every removed line in a regenerated artefact, not every removed top-level entry. Any generator that harvests by source adjacency rather than an explicit id or tag has this hazard.
- A generator refuses rather than emitting a partial artefact: a stale file is recoverable, a truncated published contract is not.
- A hand-rolled parser for a specified format throws on unrecognised syntax rather than guessing. Prefer a real parser.
- Emit in a stable order (sort keys and paths); an unsorted regeneration buries the semantic diff.
- **A comment-only or type-only edit still needs the generation control** (rebuild shared types, then `db:generate` reports no schema change). "It only touched prose" is an assumption until the generator says so.

## Handoffs and carried facts

- **In a handoff the items marked "verify" are the safe ones.** The errors live in the flat statements, above all a guess with a rationale attached beside measured facts. Re-derive every item and mark provenance per claim (measured, read off call sites, inferred).
- **A true conclusion carrying a fabricated mechanism is worse than no mechanism**, because the true half protects the false half from re-examination. An agent reported that tests failed "in `beforeAll` on the run-wide `jsonwebtoken` mock", inferred from a stack frame and stated as a measurement; the conclusion ("pre-existing on main") was right, and the actual cause was an unset environment variable. State mechanisms only when measured and mark inferred ones as inferred: a stack frame says where a throw surfaced, not why. A causal hypothesis about a test-environment difference is usually cheap to falsify by matching environments one variable at a time. Suites that self-default some environment variables (`process.env.X ??= '…'`) and rely on ambient values for others produce a partial red in a bare shell, which reads as a genuine regression where a total failure would read as a broken environment.
- **A finding about a copied model does not transfer between sibling repositories.** Oxy apps are scaffolded from one another, so a shared file is the strongest invitation to skip re-derivation and exactly where they have diverged. Re-derive per repository and cite the repository with every claim.
- **A number repeated from memory is an assertion, not a measurement**, whoever repeats it. Cite source and date, or treat it as unverified.
- **"X has not happened yet" is the one observation that expires on its own.** A census is a measurement of a commit, not of a repository: re-measure against the tree a document will land on, immediately before writing, and state the commit a count or an absence was measured at. The longer and more thorough the audit, the wider the window.
- **When two agents' accounts disagree, go to the artefact and report only that they disagree.** A peer can say what the code says; only the lead says what it should be. An apparent disagreement can be two correct measurements of two different refs (`origin/main` versus a stale branch), so state the ref alongside every measurement.
- **A split that sums exactly to its total was apportioned, not measured.** A number derived by subtraction from a grep total carries no independent information.
- **The instruction file an agent loads is the working tree's copy, not the committed one.** A stale uncommitted edit in a shared checkout briefs every session that starts there. Pin any instruction-file claim to a ref (`git show origin/main:<file>`).
- **`docs/`, `AGENTS.md`, code comments and log strings are where a wrong statement survives forever.** When a migration removes a technology, sweep comments and prose too, and check whether any of it feeds a generated artefact.
- **An instruction that can no longer be followed is worse than a wrong statement.** "Re-run the census before cutover" addressed to a reader whose source store is destroyed forces fabrication or a block. Answer from whatever archive survives and record what would reopen each instruction.

## Merging and CI

- **Gate merges on check identity, not counts.** "No checks reported", third-party-only checks and a stacked PR on a topic branch all give `fail=0 pending=0` with zero real jobs; so does a forge API outage that makes `gh pr checks` return nothing. Assert that expected job names are present and `SUCCESS`; missing equals failing.
- **A PR opened seconds ago has no checks yet**, and in a repository without required checks `gh pr merge` merges it on the spot. Require at least one registered check and a minimum PR age before treating "nothing pending" as green.
- **`gh pr merge --delete-branch` on a repository with required checks closes the PR.** The merge silently becomes "enable auto-merge", the head branch is deleted, and GitHub closes a PR whose head is gone. Never combine `--delete-branch` with a merge that may queue; delete the branch after the merge is confirmed, or let the repository's auto-delete setting do it.
- **With a merge queue, `gh pr merge --squash` does not enqueue.** It prints that the merge strategy is set by the merge queue, exits 0 and leaves the PR open, which a poller reads as "queued" and waits forever. Run plain `gh pr merge` and expect `already queued to merge`. The queue runs its own `merge_group` pipeline on `gh-readonly-queue/…`; if that fails the PR silently drops back to `OPEN`/`CLEAN`, so check `gh run list --event merge_group`, not just the PR state.
- **Read the latest run of each check, not every run in the rollup.** A re-pushed PR keeps the superseded run's `cancelled` entries beside the live run's pending ones.
- **When a run does not appear, ask whether the PR is still open before asking whether the queue is slow.** A conflicting PR, third-party-only checks and pushing to an already-merged PR's branch all give `total_count: 0` and read like a queue.
- **`gh run rerun` is refused while any job of the run is still in progress**, and the message blames "its workflow file may be broken". Wait for `status: completed`, then rerun the failed job. It prints nothing on success, so read back `run_attempt` to confirm.
- **`gh pr edit --title`, `--base` and `--body-file` can fail with only a Projects (classic) deprecation error and leave the change unapplied** (it exits 1; a draft-marked title was once squash-merged because of this). Use `gh api -X PATCH repos/<o>/<r>/pulls/<n> -f title=… -f base=…`, or pass `--body-file` at `gh pr create`, and read the title back before queueing. Check the exit code, not the look of the output: `cmd 2>&1 | tail -2; echo $?` reports `tail`'s status, so use `${PIPESTATUS[0]}`, `set -o pipefail` or run the command unpiped. `gh pr view … > body.md` truncates the target before running, so a failed fetch leaves an empty file.
- **Recurring CI failures are causes, not luck.** Install tools from a pinned, checksummed artefact rather than a package mirror in every shard; give a Jest process an explicit heap on a small runner (`NODE_OPTIONS=--max-old-space-size=…`) instead of adding a shard to answer an out-of-memory exit; and never write a test that sleeps a fixed time and counts, or mints a one-second token. Wait for the condition with a deadline; never assert how many timer ticks fit in N ms.
- **A job can report `failure` having run zero tests.** A runner that could not download an action or install the toolchain during an upstream outage fails the job under a test job's name. Compare the job's check-runs on the base SHA before reading a named red as an accusation against code the diff never touched.
- **A job that exceeds `timeout-minutes` is reported as `cancelled`**, which reads as "someone cancelled it" or "a newer push superseded it". Three causes share the one field (concurrency supersession, timeout, manual or infrastructure abort), and only the timestamps separate them: compare `completed_at - started_at` with the job's `timeout-minutes`. A job whose normal duration exceeds about two-thirds of its timeout fails intermittently for reasons unrelated to any diff; the fix is headroom, not repeated reruns.
- **A failed results upload after a successful CodeQL run reads two opposite wrong ways** (the aggregate check goes `neutral`, the matrix job `failure`). Read alerts back from `GET /repos/<o>/<r>/code-scanning/alerts?ref=refs/pull/<N>/head&state=open` and check paths against the PR's changed files.
- **Assert PR head equals the remote tip** (retry once; lag looks like a frozen head), and merge stacks bottom-up. A retarget alone runs nothing: after the parent merges, rebase and push; never merge on the retarget.
- **Gating the PR is not gating the merge.** A deploy workflow triggered on `push` with no `workflow_run` gate or `needs:` starts in parallel with CI and, being faster than a full test suite, wins the race: a merge can reach production while the same commit's tests are still running. Read the deploy workflow's `on:` block, and check the deploy run for the merge commit.
- **A task definition revision not changing is not evidence nothing rolled out.** Under `--force-new-deployment` against a mutable tag the revision is constant by design. Resolve the running task's `imageDigest` back to a commit, paired with a payload marker that disappears in the new build. For the same reason `git merge-base --is-ancestor` says nothing about what a task will run when the definition pins a mutable tag; pin digests where you can.
- **For a deploy, "how far did it get?" is the right question, and the workflow's conclusion cannot answer it.** A failed deploy spans "the runner could not download an action" (production untouched, ECS `PRIMARY`, rollout `COMPLETED`, old revision) to "the migration applied and the rollout then failed", and a workflow `success` can mask a rollback. ECS is the authority, not the workflow. GitHub omits skipped steps from a job's step listing, so a numbering gap is not a record of what ran; and work passed as an input to an earlier step (a post-rollout migration command) never was a separate step. Ask the database what applied, and read what the step printed, before asking what step number it was.
- **A branch that diffs add-only against the wrong base is a revert wearing a feature's title.** True of a PR split made after the combined PR merged, and of a branch cut before a merge and left stale while the same feature landed through other PRs. Diff against the current remote tip.
- **A job's presence says nothing about which tests it ran.**
- **During a forge outage, git writes and forge writes fail independently.** A branch can exist while its PR was never created, indistinguishable from a merged-and-deleted branch by local signals. After an outage, check `gh api "repos/<o>/<r>/pulls?head=<owner>:<branch>&state=all"`: an empty array means no PR ever existed.
