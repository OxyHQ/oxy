# Forge advisory remediation proof proposal (inactive)

This proposal does not change the audit gate, CI, acknowledgement lists or production. The existing gate remains authoritative and PR1516 stays blocked. No synthetic version or audit suppression is permitted. The script always returns `approved: false` and exits 1, including with complete candidate evidence.

Candidate interface: `node scripts/forge-remediation-proof-proposal.mjs ROOT RAW_AUDIT_JSON MANIFEST_JSON PATCH_FILE TEST_EVIDENCE_JSON`. ROOT must be the complete installed repository/image filesystem scope, not a filtered workspace or only its top-level node_modules. Traversal follows realpaths (including symlinked Bun stores), deduplicates them and reads every discovered node-forge manifest; unreadable paths or absent shipped distributions fail. It must run against both all-workspace and production-image installations. It does not install packages or run tests itself.

The manifest requires exact `package: node-forge`, `version: 1.4.0`, `advisory: GHSA-86w9-cpqp-85rv`, SHA256 `patchSha256`, `files` mapping for lib/rsa.js and both shipped minified bundles and their maps, `testEvidenceSha256`, and `independentSecurityReview: {reviewer, reviewedPatchSha256}`. All hashes are real 64-character lowercase SHA256 hex; absent fields and placeholders fail. The reviewer string is evidence metadata, not authentication or approval. Review authenticity and the separate parent policy decision must be established externally before considering any future wiring.

Test evidence binds `patchSha256`, `inventorySha256` (SHA256 of JSON.stringify of the returned sorted copies) and six exact suites with `pass` status: rsa-regressions, forge-suite, browser-bundles, expo-certificates, expo-update-signing, production-image. Run records and independently inspected output must substantiate those assertions; self-authored JSON alone cannot establish trust. The separate regression harness must cover valid digests/NULL semantics, nested extras, nonempty NULL, outer/trailing/wrong-digest malformed input and stock negative controls.

Raw advisory JSON remains visible in the result. Exactly this single Forge high advisory is eligible for candidate consideration; a changed ID/severity, another Forge advisory, absent audit, different installed version, another unpatched copy, missing bundle/map, mismatched patch/file/test hash, missing suite or absent/mismatched review fails. Other packages remain entirely subject to the unchanged audit gate; this proposal neither assesses nor acknowledges them. This check cannot prove that the nominated ROOT includes omitted external installs: integration must explicitly establish installation coverage and image provenance.

No real patch or review hash is preapproved or prepopulated. Before any future gate design, independently review both the cryptographic fix and these proof semantics; collect full Forge/Expo tests and production-image byte proof, and obtain the parent's explicit policy decision. Do not interpret technicalEvidenceComplete as security approval.
